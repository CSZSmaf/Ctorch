# 性能与内存

模型的耗时包括矩阵计算、张量寻址、数据复制和内存分配。CUDA 后端使用 cuBLAS、cuBLASLt、cuDNN 和通用 CUDA 内核，CPU 后端使用类型化循环和 BLAS。

## CUDA 计算与显存复用

### 简化张量寻址

转置、切片和广播通过形状与步长访问数据。CUDA 内核把线性下标转换成各轴坐标，再计算存储偏移。连续轴先合并，单例轴直接省略，连续张量通常只需要一次乘法。

逻辑元素数在 32 位无符号整数范围内时，坐标转换使用 32 位除法；更大的张量使用 64 位除法。步长和存储偏移始终保留 64 位，因此较大的切片间隔也能直接表示。最外层坐标已经落在该轴范围内，可以省去最后一次除法和取余。

两种整数宽度共用一个 C++ 模板。卷积偏置广播、逐元素计算、归约和带步长的优化器更新共用这条寻址路径。相关实现可参阅 [PyTorch 的 CUDA 张量索引](https://github.com/pytorch/pytorch/blob/main/aten/src/ATen/cuda/detail/TensorInfo.cuh)。

### 转置时同时转换精度

低精度 cuDNN 卷积使用通道连续的 NHWC 存储。张量的逻辑形状为 NCHW，进入卷积和返回 FP32 结果时需要调整存储顺序。

合并连续轴后，NCHW 与 NHWC 之间的转换可以表示为一批二维矩阵的转置。CUDA 复制内核按 32×32 的块读取数据，在共享内存中交换行列，再按目标类型写出。读取和写入都让相邻线程访问相邻位置，类型转换与转置共用一次读写。每行共享内存多留一个元素，使转置读取分散到不同的存储单元，减少访问冲突。

普通矩阵转置、批量转置和这类通道布局转换使用同一个 C++ 模板。FP16、BF16、FP32 等存储类型在编译期选择，逐元素转换使用统一的舍入规则。较窄的矩阵、切片和其他带步长的布局使用通用索引路径。

复制、`clone()` 和 `astype()` 自动选择对应路径。低精度计算的输出、主参数、梯度和优化器状态使用 FP32。分块转置的访存方式可参考 [NVIDIA CUDA 最佳实践](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html#shared-memory-in-matrix-multiplication-c-aat)。

### 直接读取低精度存储

两个输入都是 FP16 或都是 BF16 时，加、减、乘、除和幂运算直接读取 16 位元素，在寄存器中转成 FP32 后计算。输出和梯度仍为 FP32。这样省去两份完整的 FP32 输入副本，也省去对应的 CUDA 转换内核。

CPU 与 CUDA 各自复用原有的二元遍历模板。连续输入、转置、切片和广播使用相同的运算公式，C++ 模板只选择存储类型与计算类型。不同精度的输入继续在数值入口统一类型，应用代码无需选择内部路径。

例如，两个 `1024 × 1024` 的低精度张量相乘，输出占 4 MiB。直接读取输入后，这次运算的额外活跃显存从 12 MiB 降为 4 MiB，其中不包含调用前已经存在的输入。

### 连续转换的向量读写

矩阵乘和卷积的混合精度计算需要把 FP32 数据转成 FP16 或 BF16。连续且地址对齐的转换每个线程处理四个元素，使用对齐的 C++ 结构体读取和写入一组数据。编译器可以把相邻元素的访问合并为较宽的访存指令，减少指令数量和地址计算。

各元素仍使用同一个类型转换函数，舍入规则不变。末尾不足四个元素的部分逐项处理，带偏移或步长的视图继续按其布局访问。复制、普通转换和分块转置共用结果写入的模板。向量访存的原理见 [NVIDIA 的 CUDA 向量读写说明](https://developer.nvidia.com/blog/cuda-pro-tip-increase-performance-with-vectorized-memory-access/)。

Linear 和矩阵乘在两个 FP32 输入都需要转成相同低精度时，可以合并提交转换。两个输入分别分配结果缓冲，再按各自的元素数量分配线程块。这样只启动一次内核，也适用于大小不同的输入与权重。已有目标精度的数据直接复用，其他布局沿原有转换路径处理。

### 转换卷积结果时加入偏置

低精度 cuDNN 卷积先以 FP16 或 BF16 写出结果。Ctorch 在将结果转成 FP32 并恢复逻辑布局时，同时加上通道偏置，省去单独的偏置内核和一次完整结果的读写。

这一计算复用普通复制的遍历方式：连续数据使用向量读写，适合转置的布局使用共享内存分块，其余视图使用步长寻址。转换后的值再与 FP32 偏置相加，保留原有运算顺序。卷积的公开输出和梯度仍为 FP32，普通 `conv2d` 和 `nn::Conv2d` 会自动使用这条路径。

### 转换对完整训练的影响

下面比较分别提交转换与合并转换时的 BF16 完整训练耗时。两种实现使用相同输入、初值和训练步骤，交替运行三轮；表中取三轮中位数。模型尺寸、环境和计时方法见[框架结果对比](projects/comparison.md#cuda-训练步耗时)。

| 模型 | 分别转换 / ms | 向量与合并转换 / ms | 耗时降低 |
| --- | ---: | ---: | ---: |
| MLP | 0.256 | 0.241 | 5.9% |
| 卷积加大分类头 | 2.389 | 2.387 | 0.1% |
| 三层卷积加全局平均池化 | 0.907 | 0.876 | 3.4% |
| 单层编码器 | 1.047 | 0.991 | 5.3% |

每个训练步的 CUDA 内核调用数也有所减少：MLP 从 21 次降至 19 次；卷积加大分类头从 31 次降至 29 次；三层卷积加全局平均池化从 64 次降至 60 次；单层编码器从 95 次降至 88 次。

四组 BF16 训练的活跃显存峰值保持相同。这里的收益来自减少转换指令、内核提交和结果的重复读写。

带大分类头的卷积网络主要受参数更新开销影响，这项优化没有带来稳定的完整训练收益。

### 二分类损失的合并计算

`binary_cross_entropy_with_logits` 同时用于二分类、多标签分类和逐像素分类。输入为分数 x 和目标 y，逐项损失为：

<div data-tex="\max(x,0)-xy+\log(1+\exp(-|x|))" data-display="true"></div>

前向一次遍历计算线性项与对数尾项，不生成两份 Softplus 结果和加权乘积。`log1p` 保留接近零的损失。反向从原始输入计算导数，直接写入梯度目标；平均损失的缩放也在这次遍历中完成，标量种子无需展开成完整张量。

这类稳定表达式也用于 [PyTorch BCEWithLogitsLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.BCEWithLogitsLoss.html) 和 [TensorFlow sigmoid_cross_entropy_with_logits](https://www.tensorflow.org/api_docs/python/tf/nn/sigmoid_cross_entropy_with_logits)。Ctorch 保留 `none`、`sum`、`mean`、目标梯度和共享输入的梯度累计。

下面比较二分类损失由基础算子组合和合并计算时的完整训练步耗时。MLP 使用 `256 → 256 → 64` 的两层 Linear，批量大小为 256。卷积网络使用 `3 → 16 → 16 → 4` 的三个卷积层，输入为 `[16, 3, 32, 32]`。两个网络均使用 ReLU、浮点软标签和 AdamW，计时包含清空梯度、前向、损失、反向及参数更新。

测量设备为 NVIDIA GeForce RTX 5090 Laptop GPU，使用 CUDA 13.2 和 cuDNN 9.21。输入提前放入 GPU，每个进程预热 120 步，再测量 9 组，每组 60 步；宿主计时在每组边界等待 CUDA 完成。两种实现交替运行三轮，表中取各轮中位数的中位数。BF16 使用自动混合精度，参数、梯度和优化器状态保持 FP32。

| 网络 | 计算精度 | 组合算子 / ms | 合并计算 / ms | 耗时降低 |
| --- | --- | ---: | ---: | ---: |
| MLP | FP32 | 0.3135 | 0.1844 | 41.2% |
| MLP | BF16 | 0.3356 | 0.2085 | 37.9% |
| 卷积网络 | FP32 | 0.4461 | 0.3339 | 25.2% |
| 卷积网络 | BF16 | 0.6259 | 0.4956 | 20.8% |

这两种小网络的二分类损失占用了较多算子调用。更大的网络或使用其他损失的训练，收益取决于相应计算在整个训练步中的占比。

### 归约中的线程协作

求和、Softmax、归一化和交叉熵都需要合并多个线程的计算结果。CUDA 的一个线程束包含 32 个线程。Ctorch 将各线程的局部值写入共享内存，再由一个线程束按固定树形顺序合并。跨线程束的部分在寄存器中计算，最后 32 个值通过 shuffle 指令合并。

求和与最大值共用这一遍历过程，通过 C++ 模板选择合并规则。Softmax、LayerNorm、RMSNorm、交叉熵和梯度范数调用同一个内部归约函数。固定的 256 线程配置保留原有加法顺序，将线程块同步从 10 次减少为 3 次。所有线程取得最终值后，可以继续处理下一行。

线程束操作的说明见 [NVIDIA CUDA 编程指南](https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html#warp-shuffle-functions)。

### 并行处理较大的池化窗口

自适应平均池化把输入划分为若干窗口，分别求平均值。全局平均池化将每个通道压缩为一个值，也是这一操作的常见用法。

较小的窗口由一个线程处理。窗口较大时，一个线程块分工读取窗口内的像素，再调用公共归约函数合并结果。这样可以让相邻线程读取相邻位置，也避免一个线程串行遍历整张特征图。1D 和 2D 自适应平均池化共用这条路径，转置和切片通过张量步长访问。

反向传播将输出梯度除以窗口面积，再分配给窗口内的输入。输入尺寸能被输出尺寸整除时，各窗口互不重叠，每个像素只由一个线程更新。其余情况使用原子加法合并重叠窗口的贡献。已有计算分支的梯度继续保留并累加。

### 合并 Linear 的矩阵乘和偏置

Linear 计算 <span data-tex="Y = XW^{\mathsf T} + b">Y = X Wᵀ + b</span>。如果先计算矩阵乘，再逐元素加偏置，就需要额外提交一次 CUDA 内核，并重新读取和写入输出矩阵。

对连续且地址满足 16 字节对齐的输入、权重和向量偏置，Ctorch 使用一次 cuBLASLt 调用完成这两个操作。它将行主序缓冲视为列主序矩阵，直接计算 <span data-tex="Y^{\mathsf T} = WX^{\mathsf T} + b">Yᵀ = W Xᵀ + b</span>。偏置的列间距设为零，使同一向量用于所有样本。输入、权重和输出都无需为此转置或复制。

同一设备上，相同形状和精度复用已有的矩阵描述和计算方案。首次使用时查询方案，命中缓存的调用只提交数据地址和工作区。缓存最多保存 64 个方案，工作区按所选算法的实际需求分配，上限为 32 MiB，并在训练步之间复用。

这条路径支持 FP32、FP16 和 BF16 输入，低精度乘法使用 FP32 累积和输出。无偏置时直接计算矩阵乘；其他偏置广播形式或特殊布局使用原有矩阵乘和加法。反向传播继续将输入梯度和权重梯度直接写入各自的累计目标，偏置梯度沿样本维求和。

算法与布局的说明见 [cuBLASLt 文档](https://docs.nvidia.com/cuda/cublas/index.html#using-the-cublaslt-api)。cuBLASLt 随 CUDA Toolkit 提供，普通 `dl::linear` 和 `dl::nn::Linear` 调用会自动使用适用的实现。

### 让相邻线程读取相邻元素

对形状为 `[rows, columns]` 的连续矩阵，`sum(input, {0})` 沿行求和，得到每一列的总和。如果一组线程只计算一列，相邻线程读取的地址会间隔 `columns` 个元素。列数较多时，一次显存访问中实际用到的数据比例较低。

Ctorch 让相邻线程分别负责相邻列，每个线程先累计 64 行，再用相同的算法合并各分区的结果。这样每轮读取都沿一行连续进行。每个输出位置只有一个线程写入，无需原子加法。`amax` 使用相同的遍历方式。需要分区但并行任务较少时，仍使用原有归约路径，减少内核启动。

连续张量的前导维归约都可以使用这条路径。例如，`[batch, length, width]` 沿前两维求和时，可以视为 `[batch * length, width]` 的矩阵。Linear 偏置梯度和广播梯度中的对应求和也会使用它。转置、切片和其他归约轴继续按张量步长访问。

分区大小是编译期常量，求和与最大值通过模板选择，内层循环只执行所需运算。每个线程用四个独立累加器处理不同的行，最后两两合并，减少连续依赖和连续舍入。分区会改变浮点加法的顺序，结果可能有少量舍入差异。

在 NVIDIA GeForce RTX 5090 Laptop GPU 上，对连续的 `4096 × 1024` FP32 张量测得以下 CUDA event 耗时。两个版本都启用相同的缓冲复用。每个算子预热至少 200 ms，再测量 7 组，每组执行 20 次；表中取三轮独立测量的中位数。

| 运算 | 原实现 / μs | 当前实现 / μs | 加速比 |
| --- | ---: | ---: | ---: |
| 跨行求和 `sum(input, {0})` | 82.04 | 18.48 | 4.44× |
| 跨行最大值 `amax(input, {0})` | 81.43 | 19.38 | 4.20× |

### 在训练步之间保留空闲显存

CUDA 张量默认使用专用的异步内存池。张量释放后，空闲空间留在池中供后续分配复用。读取损失或等待 GPU 完成时，内存池也继续保留这些空间。普通 CUDA 训练无需额外添加内存作用域。

`dl::cuda::memory_stats()` 的 `used_bytes` 表示仍在使用的分配，`reserved_bytes` 还包含池内的空闲空间。一个训练阶段结束后，可以调用 `dl::cuda::release_unused_memory()` 释放 cuBLASLt 和 cuDNN 的缓存工作区，并归还池内空闲空间。仍被张量持有的存储继续有效。

```cpp
dl::synchronize(dl::Device::cuda());
const auto stats = dl::cuda::memory_stats();
std::cout << stats.used_bytes << ' ' << stats.reserved_bytes << '\n';
dl::cuda::release_unused_memory();
```

需要限制缓存保留量时，可以调用 `dl::cuda::set_memory_release_threshold(bytes)`。设为零后，Runtime 会在同步点尝试回收空闲空间。阈值控制缓存保留策略，不是整个程序的显存容量上限。完整示例见 [cuda_memory.cpp](../examples/cuda_memory.cpp)。

### 转交反向传播中的梯度缓冲

`reshape`、`flatten`、`squeeze` 和 `unsqueeze` 的反向传播只需恢复原输入形状，梯度的元素值不变。`clone` 的反向也直接传递梯度。如果每经过一个这样的节点都复制梯度，就会增加临时显存和设备复制操作。

Ctorch 在这些节点之间转交独立且连续的梯度缓冲。C++ 的移动操作转交存储句柄，显存中的元素保持在原位置。首次贡献直接成为目标梯度，已有贡献则继续原地累计。类型转换生成的独立结果和默认标量种子也使用同一套转交方式。

通过 `dl::grad` 请求的中间梯度需要保留其值。存储仍由其他结果持有时，累计目标使用独立副本。调用方传入的反向种子也保持独立。这样，求中间梯度、分支汇合和多次梯度累加仍使用原来的接口和数值规则。

### 直接写入梯度目标

一个张量参与多个计算分支时，各分支的梯度需要相加。例如，`gelu(x) + x * 0.25` 同时包含激活函数和缩放的梯度贡献。

一元函数和缩放的反向计算直接写入梯度目标。首次贡献覆盖目标，后续贡献在计算导数时完成累加，省去单独的临时张量和相加操作。求和与均值的反向传播使用同一缩放入口，输入梯度可以按广播布局读取。

内部数值层提供分配结果和写入已有结果两种入口，二者共用后端公式。CPU 和 CUDA 使用相同的覆盖与累加约定。普通算子调用和 `backward()` 会自动使用这些实现。

### 批量更新参数

CUDA 后端将最多 32 个连续参数的更新描述放入同一份内核参数表。一个参数保留自己的学习率、权重衰减和状态，多个参数可以在同一次提交中更新。SGD、Adam、AdamW、RMSprop 和 Adagrad 共用这套遍历方式。

批量内核中，每个线程一次处理四个元素，并复用参数描述和更新系数。各轮中相邻线程访问相邻元素，循环次数在编译期展开。每个元素继续使用原来的动量、矩估计和参数更新公式。张量末尾按实际元素数处理，带步长的参数使用对应的布局内核。

线程内处理多个元素的方式可参考 [NVIDIA 的执行配置说明](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html#execution-configuration-optimizations)和 [PyTorch 的多张量更新实现](https://github.com/pytorch/pytorch/blob/main/aten/src/ATen/native/cuda/MultiTensorApply.cuh)。

### 资源回收中的设备选择

CUDA 资源回收也有宿主调用开销。释放张量、事件或库句柄时，只有目标设备与当前设备不同时才需要调用 `cudaSetDevice`。这一处理集中在资源管理层，模型代码继续使用原有接口。

### 测量完整训练步

单个算子变快后，完整训练的收益还取决于它原本占用多少时间。矩阵乘、卷积、数据传输和优化器更新仍然需要执行。测量时将输入提前放到 GPU，先预热，再对包含清空梯度、前向、反向和参数更新的整个训练步计时。

CUDA 算子异步提交。宿主计时需要在测量边界等待 GPU 完成；CUDA event 则应记录在执行计算的 stream 上。调用 `loss.item<float>()` 会把标量传回 CPU，适合按日志间隔使用。

比较两个实现时，在同一轮测量中交替运行新旧版本，并保持输入、权重、精度、预热次数和训练步骤一致。其他程序会影响 GPU 频率、可用带宽和调度，应选择没有并发计算任务的时段。不同机器或不同负载下的历史耗时不能直接用来计算优化幅度。

MLP、卷积网络和单层编码器的完整 CUDA 训练步耗时见[框架结果对比](projects/comparison.md#cuda-训练步耗时)。

定位瓶颈时，可以使用 [CUPTI Activity API](https://docs.nvidia.com/cupti/main/main.html) 统计预热后的内核执行时间。下面三种训练结构使用 FP32，来自同一组 CUDA 测量，比例按各模型全部计算内核的执行时间计算。

| 训练结构 | 主要耗时 |
| --- | --- |
| 两层 MLP | 矩阵乘约占 78% |
| 单层卷积加大分类头 | AdamW 参数更新约占 55% |
| 三层卷积加全局平均池化 | 卷积计算约占 72% |

FP32 AdamW 更新一个参数需要读取参数、梯度、一阶矩和二阶矩，并写回参数及两个矩，至少传输 28 字节。大分类头包含较多权重，因此参数更新会占用较多显存带宽。三层卷积网络的分类头较小，主要耗时集中在卷积的前向与反向计算。

内核记录用于定位计算热点。完整训练的加速比例由关闭分析工具后的整步计时确定，不能把某个内核的降幅直接当作模型的降幅。

数值对照可以同时比较连续训练和固定状态的单步结果。连续训练中，浮点舍入会影响后续参数，ReLU 等分段函数在接近分界的位置还可能改变梯度分支。固定每步的参数与优化器状态后，可以直接比较前向、梯度及更新公式。随机种子控制随机采样；CUDA 原子归约和设备库算法的执行顺序也会影响逐位一致性。

内存池的行为见 [CUDA 异步内存分配说明](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/stream-ordered-memory-allocation.html)。

## 在 CPU 训练循环中复用内存

在循环外创建一个 `dl::MemoryGuard`。作用域内的普通张量分配会使用同一个缓冲池，前向、反向和优化器更新都可以复用空闲块。

下面是完整的 CPU 训练程序：

```cpp
#include <dl/dl.h>
#include <iostream>

int main() {
    dl::manual_seed(42);
    auto input = dl::randn({64, 3});
    auto target = dl::sum(input, {1}, dl::KeepDim::yes);
    dl::nn::Linear model(3, 1);
    dl::optim::SGD optimizer(model.parameters(), {.learning_rate = 0.05});

    dl::MemoryGuard memory;
    for (int step = 0; step < 100; ++step) {
        optimizer.zero_grad();
        auto loss = dl::mse_loss(model(input), target);
        loss.backward();
        optimizer.step();
        if (step % 20 == 0) std::cout << loss.item<float>() << '\n';
    }

    const auto stats = memory.memory_stats();
    std::cout << "reserved bytes: " << stats.reserved_bytes << '\n';
    std::cout << "in-use bytes: " << stats.in_use_bytes << '\n';
    memory.release_unused_memory();
}
```

构建方式见[第一次训练示例](../examples/first_training.cpp)和[构建手册](build.md)。对已有程序，通常只需在反复执行的计算外增加 `dl::MemoryGuard memory;`。

作用域应覆盖整个循环。若每次迭代都重新创建作用域，空闲块也会在每次迭代结束时释放。

## 缓冲何时可以复用

张量、视图和反向传播保存值共同持有存储。最后一个持有者释放后，这块存储才进入空闲状态。例如，前向结果仍被损失函数保存时，下一次计算会使用其他缓冲。

`MemoryGuard` 退出时释放空闲块。仍被张量持有的块会继续存活，因此输出可以返回到作用域外。每个执行线程创建自己的作用域，张量的最后一个引用可以在消费线程释放。嵌套作用域结束后恢复外层缓冲池。

`memory_stats()` 的 `reserved_bytes` 包含空闲和使用中的存储，`in_use_bytes` 只包含仍被持有的部分。输入尺寸经常变化时，池中会积累多种大小的块，可以在一个计算阶段结束后调用 `release_unused_memory()` 归还空闲块。

固定执行计划已有自己的工作区和 `with_memory` 方法。它与普通训练作用域使用同一套缓冲管理机制，见[组合与执行](execution.md)。

## C++ 循环如何影响性能

### 将布局判断放在内层循环之外

连续张量的地址逐元素递增。广播标量的地址保持不变。把这两种步长在循环外确定下来，内层就只需读取、计算和写入。Ctorch 用局部模板区分步长为 0、1 和一般步长的情况，使常见路径的步长成为编译期常量。

ReLU 等简单操作使用具有具体类型的 lambda。编译器能够看到操作体，更容易将它内联到数据循环中。模板本身不会在每个元素上执行额外的运行时分派。

### 减少 Transformer 中重复的逐元素计算

Dropout 先生成布尔掩码，再根据掩码保留并缩放输入。数据指针在进入循环前取得，前向和反向共用已有的二元遍历函数。连续输入走固定步长路径，转置和切片沿各自的步长访问。

因果注意力通常用负无穷屏蔽每行末尾的未来位置。Softmax 可以直接将这些位置写为零，只对前面的有效范围计算指数和归一化。LogSoftmax 对应的位置写为负无穷。整行都为负无穷时，结果为 NaN。

GELU 使用误差函数 `std::erf`。公式中的固定系数用 `constexpr` 表示，循环通过乘法计算缩放后的输入和高斯密度。改写除法会产生小幅浮点舍入差异，因此比较时需要同时检查前向、梯度和连续更新后的参数。

### 按行处理卷积和池化

卷积展开窗口时，同一行共用输入起点和有效列范围。连续部分使用 `std::copy_n`，带步长的视图则沿固定步长访问。池化按平面、行、列遍历，减少从线性下标反复解算空间坐标的整数除法。

归约到同一个输出的行使用局部累加器。内层计算完成后写回结果，保持原有求和顺序。

### 区分表达式与实际计算次数

下面的表达式很短，但在 eager 张量接口中会执行多次算子调用：

```cpp
auto output = ((input - mean) * inverse_std) * weight + bias;
```

每个算子通常产生一个结果张量。C++ 编译器看到的是这些函数调用，不能自动把运行时的张量计算图合并成一个循环。缓冲复用减少分配和释放；算子融合则进一步减少中间结果的读写。两者解决的开销不同。

Ctorch 保留独立输出与原地更新的接口区别。原地累计可以读写同一份存储，因此通用循环使用普通指针，不给这些路径附加不重叠假设。

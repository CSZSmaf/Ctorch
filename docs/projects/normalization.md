# 归一化与完整训练

BatchNorm 的通道归约减少了完整尺寸的中间张量和 CUDA 内核调用。在下面的同轮测量中，ResNet-20 的 FP32 与 BF16 完整训练耗时分别降低 54.0% 和 50.3%。MLP 和不含 BatchNorm 的卷积网络变化较小。

## 计算方式

BatchNorm 将每个通道的样本与空间位置分区，分别计算均值和中心平方和，再合并成通道统计。前向直接完成归一化、缩放与偏置，反向共同计算两个通道归约并写入梯度目标。中间结果的大小取决于通道数与分区数，不随整个特征图复制。

LayerNorm 与 RMSNorm 的反向也直接写入梯度目标。一个参数参与多个分支时，后续贡献直接累加。C++ 数据句柄负责保存和转交存储，CPU 与 CUDA 后端使用相同的目标与累计标志。应用继续调用普通模块和 `backward()`。

实现说明与状态约定见[性能与内存](../performance.md#batchnorm-的通道归约)。

## 测量配置

测量使用 NVIDIA GeForce RTX 5090 Laptop GPU（24 GB）、Intel Core Ultra 9 275HX 和 Windows 11。Ctorch 为 C++20 Release、MSVC 19.50、CUDA 13.2 编译工具、13.4 运行库和 cuDNN 9.21；PyTorch 为 2.11.0+cu128、cuDNN 9.19、Python 3.14 和 Triton Windows 3.6。

每个训练步包含清空梯度、前向、平均交叉熵、反向和参数更新。输入提前放在 GPU，同一批输入重复训练。每项先调用一次，预热 60 次，再测量 7 组、每组 10 次，共执行 131 步。四种配置在同一组测量中交错运行三轮，共 120 个计时进程。表中为三轮中位数，单位为毫秒 / 训练步。

宿主计时在每组边界等待 GPU 完成。完整 CSV 同时记录 CUDA Event 时间、三轮范围及分配器显存。首次编译、数据读取和文件保存不计入稳态耗时。

| 配置 | 执行方式 |
| --- | --- |
| Ctorch 组合归一化 | BatchNorm 由基础算子组合，LayerNorm/RMSNorm 先生成梯度贡献再累计 |
| Ctorch 通道归约 | BatchNorm 使用通道统计内核，三种归一化直接写入梯度；Adam 的矩权重先按超参数精度计算 |
| PyTorch 优化 eager | 融合优化器、cuDNN 算法选择、低精度卷积 `channels_last`、注意力 SDPA |
| PyTorch 编译 | 在优化 eager 上使用 `torch.compile(fullgraph=True, mode="reduce-overhead")`；编译前向和损失，AOTAutograd 生成反向，优化器使用独立的融合实现 |

FP32 关闭 TF32。BF16 使用 autocast，主参数、梯度和优化器状态保持 FP32。Ctorch 低精度计算的输出仍为 FP32，PyTorch 在部分算子之间保留 BF16 激活。

| 模型 | 输入与主要结构 | 优化器 |
| --- | --- | --- |
| MLP | 批量 256，`1024 → 2048 → 1000`，ReLU | SGD，学习率 0.001，动量 0.9 |
| 卷积与大分类头 | 批量 32，`3×64×64`，32 通道卷积与 `32768 → 1000` 分类层 | AdamW，学习率 0.001，权重衰减 0.01 |
| 三层卷积 | 批量 32，`3×64×64`，通道 `3 → 32 → 64 → 64`，全局平均池化 | AdamW，同上 |
| 单层编码器 | 批量 8，长度 128，宽度 256，8 个头，前馈宽度 1024，512 类 | AdamW，同上 |
| ResNet-20 | 批量 8，`3×32×32`，残差模块、BatchNorm，10 类 | SGD，同上 |

AdamW 使用 `beta1=0.9, beta2=0.999, epsilon=1e-8`。编码器关闭 Dropout，使用前置 LayerNorm 和 GELU。其输入、标签及参数初值由种子 42 生成：输入为标准正态分布，标签均匀采样，Linear 与 LayerNorm 使用 PyTorch 默认初始化。同一份输入和初值用于所有配置。ResNet 使用[项目教程](resnet.md)的已训练权重及 4 张 CIFAR-10 测试图像，批量 8 时重复这 4 张图像。其余模型的结构和确定性初值规则见[多维性能比较](performance.md)。

### BF16

| 模型 | Ctorch 组合归一化 | Ctorch 通道归约 | PyTorch 优化 eager | PyTorch 编译 |
| --- | ---: | ---: | ---: | ---: |
| MLP | 0.223 | 0.222 | 0.740 | 0.438 |

ResNet-20 的 FP32 耗时由 PyTorch 编译配置的 6.55 倍降到 3.01 倍，BF16 由 6.64 倍降到 3.30 倍。卷积、激活、布局转换和其他反向计算仍占用时间，归一化融合尚未消除与编译执行的差距。

## 内核调用与显存

在相同 BF16 训练结构下，ResNet-20 每步的 CUDA 内核调用从 842 次降到 394 次，编码器从 88 次降到 87 次。计数使用独立的 CUPTI 采集，每个配置预热 200 步，再记录 40 步；计时表来自未启用采集的进程。

下表为 CUDA 分配器管理的显存峰值，单位 MiB，取三轮最大值。使用峰值表示仍在使用的存储，保留峰值包括池内缓存的空闲空间。

| 模型 | 精度 | 组合归一化使用峰值 | 通道归约使用峰值 | 两者保留峰值 |
| --- | --- | ---: | ---: | ---: |
| ResNet-20 | FP32 | 30.38 | 28.64 | 32 / 32 |
| ResNet-20 | BF16 | 22.73 | 20.98 | 32 / 32 |
| 单层编码器 | FP32 | 49.19 | 49.19 | 64 / 64 |
| 单层编码器 | BF16 | 50.19 | 50.19 | 64 / 64 |

ResNet 的使用峰值减少约 1.74 MiB，保留峰值保持 32 MiB。减少中间张量降低了部分使用峰值；完整模型还需要保存激活、参数、优化器状态和库工作区。分配器计数不等于进程总显存。

## 数值结果

归一化检查覆盖 248 组形状、精度和梯度场景，包括连续与非连续布局、训练与推理、无仿射参数、共享参数、分支累计和运行统计。1044 项输出、梯度及状态比较通过 FP64 参考检查。FP32、FP16/BF16 存储使用 `atol=2e-5, rtol=2e-3`；CPU FP64 使用 `atol=2e-11, rtol=2e-11`。低精度输入先量化，再交给两边计算。

Adam 与 AdamW 的矩更新需要 `1-beta`。这个差值先用超参数的 double 精度计算，再转成累积类型，使矩权重与偏差校正使用一致的系数。先把接近 1 的 beta 转成 FP32 会丢失该差值。连续与带步长参数、耦合与解耦权重衰减的 144 项多步比较通过 FP64 公式参考，最大绝对误差约 1.84×10⁻⁶。

| 精度 | 时点 | 比较数 | 超出逐元素容差 |
| --- | --- | ---: | ---: |
| FP32 | 第 1 步 | 490 | 0 |

| BF16 | 第 1 步 | 490 | 93 |
| BF16 | 第 131 步 | 490 | 94 |

### 编码器的周期性合成输入

周期性合成输入与参数初值会产生更敏感的训练轨迹。使用共同参数，在初始状态及第 64、128 步状态重新计算梯度，54 个 Ctorch 梯度张量均满足前述 FP32 容差，相对 FP64 参考的最大绝对误差为 1.3e-06。

重复同一批周期性输入 131 步时，最终损失仍有以下差异：

| 计算配置 | FP32，批量 8 | BF16，批量 1 |
| --- | ---: | ---: |
| Ctorch 通道归约 | 2.580184 | 0.475958 |
| PyTorch 优化 eager | 2.525215 | 0.522115 |
| PyTorch 编译 | 2.568608 | 0.501369 |

只把 PyTorch 数学注意力配置的初始参数向上移动一个 FP32 可表示间隔，其最终损失就从 2.538522 变为 2.552722。该负载对舍入顺序敏感，Adam 系数修正没有使各实现的长轨迹完全一致。前面计时表采用共享随机初始化，并单独保留这里的合成负载结果。浮点计算顺序的说明见 [PyTorch 数值精度文档](https://docs.pytorch.org/docs/2.11/notes/numerical_accuracy.html)。

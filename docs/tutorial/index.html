一个完整的训练程序

参数从零开始。经过 100 次 SGD 更新，权重接近 2、偏置接近 1；初始均方误差是 9。

#include <dl/dl.h>
#include <array>
#include <iostream>

int main() {
    const std::array<float, 5> x{-2, -1, 0, 1, 2}, y{-3, -1, 1, 3, 5};
    auto input = dl::from_span<float>(x, {5, 1});
    auto target = dl::from_span<float>(y, {5, 1});
    dl::nn::Linear model(dl::zeros({1, 1}, {.requires_grad = true}),
                         dl::zeros({1}, {.requires_grad = true}));
    dl::optim::SGD optimizer(model.parameters(), {.learning_rate = 0.1});

    for (int step = 0; step < 100; ++step) {
        optimizer.zero_grad();
        auto loss = dl::mse_loss(model(input), target);
        loss.backward();
        optimizer.step();
    }
    dl::NoGradGuard no_grad;
    std::cout << "weight " << model.weight().item<float>()
              << ", bias " << model.bias()->item<float>() << '\n';
}

02 / 09 TENSORS

形状会变，数据可以不动。

Tensor 将数值存储、索引布局和求导身份连在一起。理解这三者，就能理解视图与复制的区别。

观察一次转置

每个格子显示“值 / 存储下标”。选择一个元素，观察逻辑位置与底层存储之间的对应。

布局实验

共享存储 · 6 个连续的 float

transpose 改变索引步长，底层六个值的顺序保持不变。

创建与读取

const float values[] = {1, 2, 3, 4, 5, 6};
auto x = dl::from_span<float>(values, {2, 3});
auto transposed = x.transpose(0, 1);
std::cout << dl::describe(transposed) << '\n';
auto independent = transposed.clone();

describe 只读取元信息。to_vector<float>() 按逻辑顺序取得宿主数值；读取 CUDA 数据时会产生设备传输。

把视图与副本分清

操作存储与求导关系
复制 Tensor 句柄继续持有同一身份和存储。
transpose / slice建立共享存储的视图，反向映射到输入。
clone()复制数值，梯度仍可回到输入。
detach()共享存储，脱离当前求导历史。
detach().clone()获得独立、无历史的数值副本。

广播可以让 [2, 3] 与 [3] 相加。反向时，广播出来的维度会归约回输入形状。更多算子见张量与梯度手册。

03 / 09 AUTOGRAD

沿着计算，找到梯度。

一次前向记录依赖，一次反向汇总贡献。一个变量经过多条路径使用时，这些路径的梯度会相加。

约 6 分钟浏览器数学演示

两条路径，一个梯度

链式法则L = x² + x
x2.0
x × x 贡献 2x = 4.0
x 贡献 1
L6.00
dL/dx = 2x + 1 = 5.0
叶梯度 空

每次点击代表重新前向，再执行 backward。移动 x 会开始一组新的演示；连续反向会累计叶梯度。

求导与累计

auto x = dl::full({}, 2.0, {.requires_grad = true});
auto loss = x * x + x;
loss.backward();
std::cout << x.grad()->item<float>();  // 5

// 下一次前向建立新的计算图，叶梯度继续累计。
(x * x + x).backward();
std::cout << x.grad()->item<float>();  // 10
x.zero_grad();

评估模式与求导模式

model.eval() 控制 Dropout、BatchNorm 等层的行为；NoGradGuard 控制是否记录求导图。评估通常同时使用二者。

model.eval();
dl::NoGradGuard no_grad;
auto prediction = model(input);
一次更新的梯度边界

普通训练在每次更新前清空梯度。微批训练则先累计多个前向的加权损失梯度，再执行一次更新。Ctorch 当前提供一阶反向求导。

05 / 09 CUSTOM MODULES

一个层，就是一段计算。

继承 Module 管理状态，使用普通张量运算定义前向。我们从只有一个可学习参数的 Scale 层开始。

约 7 分钟可下载 C++ 示例

登记参数，再描述前向

class Scale : public dl::nn::UnaryModule {
public:
    Scale() : weight_(register_parameter(
        "weight", dl::full({}, 2.0, {.requires_grad = true}))) {}

    dl::Tensor forward(const dl::Tensor& input) override {
        return input * bound(weight_);
    }

private:
    dl::Tensor weight_;
};

register_parameter 让优化器和状态保存能发现参数；bound 让前向读取本次调用的参数。同一层的参数、buffer 和子模块共用名称空间，名称非空、无点且唯一。

同一个 forward，两份参数

参数绑定演示input = 3
3 × bound(weight) = 6

普通调用读取模块登记的参数。外部状态的更改保留在自己的存储中。

Scale model;
dl::nn::FunctionalModule functional(model);
auto state = functional.state();
state.parameters[0] = dl::full({}, 5.0, {.requires_grad = true});
auto input = dl::full({}, 3.0);
auto result = functional.call(state, dl::RandomKey{7}, [&] {
    return model(input);  // bound(weight_) 在此读取外部状态。
});

看清模型的状态

dl::summary(model) 展示模块路径、训练模式、参数量、冻结状态和共享关系；named_parameters() 提供可遍历的名称与张量。

无参数的 SiLU 层只需组合乘法与 sigmoid。涉及外部数值计算时，可以转到第 9 节注册自定义 VJP。

06 / 09 STATE & CHECKPOINTS

保存的，是哪一刻的模型？

状态表里的 Tensor 仍然连接着模型。希望留住某一时刻的参数，就创建一个独立快照。

约 6 分钟浏览器状态演示

视图会跟随，快照会停留

状态实验初始 weight = 1
model1当前参数
state_dict()1共享存储的状态表
clone_state(...)1独立数值快照
auto view = model.state_dict();
auto best = dl::clone_state(view);  // 独立 CPU 副本，脱离求导历史。
// 后续更新改变 model 和 view，best 保留采集时的数值。
model.load_state_dict(best);
dl::io::save("weights.ct", model.state_dict());

恢复训练也需要优化器状态

// 在一次 optimizer.step() 完成后保存。
auto saved = dl::io::capture_checkpoint(model, optimizer, {.step = 100});
dl::io::save_checkpoint("training.ct", saved);

// 先构造相同结构、迁移设备，再创建优化器。
auto loaded = dl::io::load_checkpoint("training.ct");
auto progress = dl::io::restore_checkpoint(loaded, model, optimizer);

训练快照包含参数、buffer、优化器槽、训练进度和默认随机流。使用 DataLoader、调度器或 GradScaler 时，把对应对象一并传给快照接口。恢复从下一个更新窗口开始。

共享参数具有稳定名称

同一张量登记在 a.weight 与 b.weight 时，以字典序最小的 a.weight 作为规范名，只更新一次。改变子模块登记顺序不改变规范名。

state_aliases() 展示其他路径与规范名的对应。加载仍接受当前模块树中的旧别名，因此旧检查点可沿相同的登记路径恢复。模型路径本身改名需要应用明确迁移。

07 / 09 DEVICES & PRECISION

把计算放到合适的设备。

CPU 与 CUDA 共享模型代码。设备迁移、前向计算精度与梯度缩放分别由清楚的接口管理。

约 7 分钟CUDA 示例需要对应构建

先迁移，再创建优化器

const auto device = dl::Device::cuda(0);
model.to(device);
input = input.to(device);
target = target.to(device);
dl::optim::AdamW optimizer(model.parameters(), {.learning_rate = 0.001});

主参数保持 FP32。autocast 选择 GEMM、卷积等算子的低精度输入，GradScaler 管理 FP16 梯度的数值范围。CUDA 构建方式见构建手册。

一个 FP16 更新窗口

dl::GradScaler scaler;
// 每次更新复用同一个 scaler，保留动态倍率。
optimizer.zero_grad();
auto loss = [&] {
    dl::AutocastGuard autocast(dl::DeviceType::cuda, dl::DType::f16);
    return dl::mse_loss(model(input), target);
}();
scaler.scale(loss).backward();
scaler.step(optimizer);  // 还原梯度、按有限性更新参数，再调整倍率。

需要裁剪时，显式还原一次

将上例最后一行替换为以下代码。unscale_ 原地还原梯度，裁剪读取还原后的数值，然后分别完成参数更新和倍率调整。

const bool finite = scaler.unscale_(optimizer);
if (finite) {
    dl::optim::clip_grad_norm(model.parameters(), 1.0);
    optimizer.step();
}
scaler.update(finite);
读取数值也有成本

CUDA 的 item() 和 to_vector() 会把数值带回 CPU。集中读取阶段指标，让连续的训练更新尽量留在设备上。

cuDNN 卷积和融合注意力属于可选后端。低精度舍入与运算次序可能不同，比较结果应使用相同输入、精度与适合该精度的误差标准。

08 / 09 FUNCTIONS & EXECUTION

固定计算结构，显式传递状态。

函数式调用把状态交给调用者。固定执行计划把可复用的计算结构交给运行时，两者都继续使用已有的张量与求导语义。

约 9 分钟浏览器结构演示

参数与随机性都可以成为输入

FunctionalModule::state() 交付独立参数和 buffer。call 读取外部参数，返回本次更新后的 buffer；调用者显式接回这些状态。

dl::nn::FunctionalModule functional(model);
auto state = functional.state();
dl::RandomKey key{73};
auto result = functional.call(state, key, [&] { return model(input); });
state.buffers = std::move(result.buffers);
++key.stream;  // 下一次前向使用新的显式随机流。
auto gradients = dl::grad(dl::mean(result.output), state.parameters);

从两次操作，到一次融合

执行计划示意
xbias
→
Add + ReLU
→output
计划操作数1
融合次数1

示意范围是相邻、单一消费者的 add → ReLU。融合减少一次调度及中间张量；这里展示结构，不测量运行速度。

dl::plan::Graph graph;
auto x = graph.input(dl::tensor_spec(input), "input");
auto b = graph.input(dl::tensor_spec(bias), "bias");
auto sum = graph.call(dl::plan::ops::add(), {x, b});
auto y = graph.call(dl::plan::ops::relu(), {sum});
auto plan = graph.compile({y});
std::cout << dl::describe(plan) << '\n';
auto workspace = plan.prepare();
auto outputs = workspace({input, bias});

何时使用固定计划

输入规格和执行路径稳定时，计划复用宿主调度结构与工作区。每次调用重新绑定输入和参数，新的求导图仍然在本次调用中建立。不同规格或路径对应新的计划。

运行时缓冲由实际持有者决定生命周期；长期保存输出会增加存活存储。计划不是通用 JIT，也不会把任意 C++ 控制流自动转换成图。多输出、激活重算与函数式组合见执行手册。

#include <dl/npu.h>

dl::npu::CompiledModel model("model.onnx", {
